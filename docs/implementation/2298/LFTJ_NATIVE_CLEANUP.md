# Registered LFTJ native cleanup

This prerequisite covers a compiler-selected LFTJ already owned by the real
serial framed host. Its saved Original may have ended while the child still
owns readers, copied inputs, a writer or private output. The registered native
cleanup destination drains that owner and its actual receipt before returning
the execution error. Default batch-off financial admission is recorded in
[LFTJ_SOURCE_ACCOUNTING.md](LFTJ_SOURCE_ACCOUNTING.md). Runtime policy is also covered there; final coverage-ledger and complete
issue qualification remain subsequent work under #2298.

## Authority and disposition

`wl_columnar_session_join_cleanup_prove` authenticates the retained session,
framed context, native thread, operation, saved attempt, private binding and
five-field receipt key. Financial funding supplies no replacement authority.
The numeric admission additionally checks its canonical embedded child, bounds
and composed state. A live LFTJ requires its actual numeric owner, frame,
session, control, saved attempt, creator thread, consumed metadata and bounded
cleanup cursor/stage. An unrelated pending action cannot inherit that owner.

The child proof validates scalar-retirement initializer and storage identity.
A `DONE` phase with retained writer, output, input array, row, reservation or
retirement debt, including the private writer-drain identity, is invalid. Historic completed LFTJ state remains usable by a
later ordinary operator in the same numeric body.

After authentication the existing registered cause is latched only where no
earlier cause exists. Native cleanup therefore preserves `EINVAL` from an
ended Original instead of replacing it with the abort primitive's default
cancellation result. The child executes its incremental abort/release path;
numeric RELEASE follows actual child completion, and numeric DONE follows a
separate metadata-clear action. The existing framed pending-result and receipt
ACK protocol retains each funding owner until its real consumption.

A different genuine Original successor may remain active during cleanup of
the registered old receipt. The old IDs and native ownership remain fixed;
cleanup never charges, finishes, resets or cancels the successor. Destruction
returns `EBUSY` while that successor owns its active generation. Its owner must
finish it separately.

## One descriptor per release action

The shared LFTJ RELEASE body selects only `cleanup_cursor`. It performs one
existing reader, rows or scratch subaction, or one paid descriptor advance,
and returns. A failed advance changes neither cursor nor stage. The last
advance also returns: row/array release, credit return and successful output
handoff occur in later actions.

Every actual descriptor advance costs one logical unit of cleanup funding,
including a descriptor with no remaining resources. Normal completion, sticky
CANCEL/WORK cleanup and registered native cleanup share this rule. Original
forward-execution tariffs are unchanged. `input_count` is the real resolution
high-water; a long allocated but unresolved tail is a component limit control,
not a claimed production failure history.

## Source metric, payments and checks

Source bounds count scalar stores, evaluated leaf predicates, arithmetic and
loop steps, complete argument/call/result/return fronts, native thread calls
and expanded project helpers. Aggregate clears count their scalar slots.
Qualified controller/native interiors retain their existing narrow boundaries.
Logical fees, source upper bounds and guaranteed processed lower bounds are
different quantities. The shared quantum remains 256.

After the complete registered proof, a live LFTJ selects a fixed numeric-owner
validation action of 32 and a child-owner validation action of 8. The embedded
identity observation selects payment only; the complete proof still precedes
native mutation. Absent or historic-DONE LFTJ retains the existing 128 numeric
admission. Historic DONE receives no new child cause.

## Failure, cleanup and library boundaries

Funding and its saved generation are checked before the new proof or advance.
A refusal retains child resources and phases. Authenticated error intent may
already have been latched by an earlier successfully paid proof; it is distinct
from resource mutation. The saved-funding zero can also refuse with that intent
retained and numeric busy released.

Reader release stages, physical allocator/free, Arrow release and mandatory
scalar/reservation retirement keep only their established interior boundaries.
Caller fronts, source scans, native-thread checks, actual first iterations and
return bookkeeping remain counted. No raw LFTJ callback or unlimited fallback
is introduced. User callbacks remain the existing prepaid publication boundary;
these failed native attempts publish no heads or callbacks.

## Prechild metadata and terminal ACK

An authentic registered native owner can end between metadata activations,
before a child is born. HEADER does not read opaque metadata or uncaptured
binding fields. Later stages prove exactly the captured metadata, name cursor,
binding snapshot/generation, registry and PREFIX/INSTALL lineage. NULL child
identity denotes canonical neverborn or prefix-cleared storage; it does not
authorize reading the uninitialized tail. A historic nonnull child must prove
real resource-free DONE. Live child debt is rejected in a metadata phase.

Metadata admission uses the same 32+8 financial split, then a genuine saved
cleanup-funding zero before the metadata proof and another before the full
nested stack-owner proof. After authentication, registered cause is retained,
metadata routes to numeric RELEASE, and a separate 128 action clears metadata
before DONE. No probe of ended Original is inserted into that drain.

The metadata-native host group ends Original between actual HEADER/NAMES,
static/dynamic binding and PREFIX/INSTALL activations. It verifies real rejected
and accepted grants, distinct active successor, frozen full report, peer
credit, source images, no publication and exact retry. Component negatives
reject mismatched operation/cursor, metadata/binding identities and generations,
registry and prefix state. Payments 31/32/39/40 remain independent financial
controls, distinct from source bounds. A 40 grant may latch intent and redirect
to RELEASE before the later metadata-clear debit refuses.

Terminal composed ACK keeps composed_busy and actual frame ownership through
full child proof and bounded 1024-byte clears. Real funding checks separate
chunks and precede final unbind. On refusal the record remains owned for
idempotent retry; its Original/report, frame-held rows and native receipt are
not replaced. Genuine host ACK cancellation histories exercise this same
protocol. See the source-accounting document for the static four-entry proof
and private output/writer retirement qualifications.
