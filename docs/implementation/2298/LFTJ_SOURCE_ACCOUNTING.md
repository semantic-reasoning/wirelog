# Serial LFTJ source ownership

This records the default serial LFTJ financial admission prerequisite for
#2298. It extends the existing framed execution destination to its public
batch-off financial host. Complete child traversal and policy qualification
are separate parts of the issue; this document does not declare them complete.

## Construction and route selection

Session creation records structural LFTJ presence by inspecting actual plan
operator enums. It reads no names, opaque metadata, source cells or cache.
For actual visited stratum/relation/operator counts S/R/O, its conservative
finite setup bound is `8 + 12*S + 12*R + 6*O`. This is pre-attempt construction,
not a claim that an arbitrary complete plan scan fits quantum 256. No arbitrary
relation/operator count cap excludes larger supported plans.

The route requires a configured control, one worker, at most 32 strata and no
recursive stratum. Structural LFTJ presence is ORed with the existing batch-on
selector. All recursive flags are still examined after LFTJ discovery. Worker
clones explicitly retain false admission. A batch-off non-LFTJ session keeps
its existing financial route. Malformed opaque LFTJ metadata is validated at
runtime, not during this structural classification.

Public admission, query and footer use the existing admission-owned BANK.
Host action, finish and the independent Snapshot financier select existing
batch-on OR the authenticated admission bit. The OR preserves older batch-on
domains outside this new narrow admission. Actual batch execution selectors,
materialized fallback flags and strict policy are separate semantic decisions.
Shared-count, coordinator, differential, TDD and recursion guards remain.

The native birth filter permits the financial LFTJ route with semantic
fallback=false. Request and context fallback flags must match. Full canonical
frame, session, plan, control, saved attempt, operation, thread, private binding,
capture and five-key receipt proofs still precede native publication. Financing
does not provide execution or cleanup authority. Mixed ordinary heads in an
admitted LFTJ session obtain the same canonical registration.

## Private output and bounded writer retirement

LFTJ owns its row scratch independently from the private output. Its counted
output pass constructs capacity for the exact duplicate product before any
row append. The owned-row entrypoint proves the actual embedded child, numeric
owner, thread, frame, output identity, writer, fully populated row and saved
Original, then reuses the checked ROW body. It bypasses generic capture and
renewal; generic row callers retain those operations. A guard after the actual
ROW shape checkpoint rejects growth or a changed width/capacity. Thus an error
cannot silently enter an unqualified allocation branch.

A failed post-ROW check may leave private nrows ahead of output_written. The
child records failure and retires the private relation; it never repeats that
append or publishes the partially written output. Writer authority is retained
even if BEGIN itself returned with a genuine partial acquisition.

RELEASE initializes a private drain in its own funded action. Subsequent actions
release one writer or clear at most four meaningful fields. The funded sibling
checks the distinct saved cleanup generation before authority work, then again
after full NEW/OWNER/DESCRIPTOR authentication and before publication or one
physical release. Release and its acquired-count publication remain indivisible.
A physical release error stays on release_error with done=false, retaining the
same authority for retry. The older unfunded drain API is unchanged.

After DONE, a separate one-unit action resets the small drain before output
retirement or child completion. A compile-time bound includes its actual clear
slots and the complete scalar return suffix. Only its identity is initialized
before birth; canonical uninitialized child storage is never read as a drain.
A historic child DONE with retained drain identity is invalid.

The 75-column, 64-row test first proves the generic capture allocation fault
really fires, then arms the same fault at actual LFTJ emission and verifies it
remains unused through all output. Literal cells and cloned raw parity are
checked separately. Direct funded drain tests cover every phase, real sticky
Original cancellation, separate funding cancellation, stale funding generation,
copied drain, wrong nonce, missing latch/batch, physical release errors and
successful retry without any Original debit.

## Composed static proofs and ACK

A static private binding table can contain four entries and six distinctness
pairs. Its complete scan cannot be justified by the fixed table size alone.
Composed validation checks its separate saved host funding before each actual
entry, each pair and the final stack-owner proof. It preserves all original
identity, thread, frame, generation, entry and pair checks. Dynamic bindings
keep the existing authenticated snapshot authorization; legacy numeric
validation is unchanged. Sticky Original is not used as cleanup funding.

The maximum-table test cuts all eleven actual check boundaries under genuine
CANCEL and WORK, verifies untouched status/record/owner, rejects stale funding
and retries with a fresh generation. The explicit WORK probe debit is test
instrumentation, not a claim about engine source work. Successful coverage
requires all four entries, all six pairs and the final proof.

ACK validates full child and frame ownership under composed_busy, then clears
at most 1024 bytes before each genuine saved-funding check. A final check
precedes owner unbind. Refusal leaves the frame/record owner retained and busy
released; partially cleared bytes may be cleared idempotently on retry. It does
not inspect neverborn child tails. Tests stop the initial, first, middle and
final checks with normal, CANCEL and WORK Original histories, reject reentry
and stale funding, and retry without changing the Original meter, held output
or registered report. The registered host exercises the same real ACK cuts.
