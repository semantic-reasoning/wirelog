## Private controller lifecycle

Ordinary private Source birth now uses one immutable-identity claim. A genuine
CAS loss returns a financial retry before publication; allocation/mutex failure
consumes the claimed identity without publishing a controller. The two real
references are creation plus attachment. Generic unlimited private financiers
retain their existing zero-limit behavior.

The additive positive-only fresh constructor initializes the actual first
attempt on an unpublished allocation: id1, active, zero consumed, Normal class,
no prior report. It publishes only after mutex and all state initialization.
It accepts no existing controller and cannot reset cancellation or history.
Only the additive early checked-birth callback selects this constructor.

Private financial completion checks owner, identity, saved generation, limits,
consumption and the real two-reference pair under the controller mutex. It
observes cancellation and publishes the report under that same lock. Ordinary
Core FINISH remains unchanged and does not itself poll cancellation. The
Session financial wrapper records actual completion before later disposal;
a successor is never finished by an old saved-generation close. Separate final
retirement requires an unexposed exclusive pair and drops its actual attachment
and creation obligations only after preserving the completed report by value.

The additive final pair authenticates complete disjoint typed extents and

financial/engine metadata work only and cannot borrow a Native owner.
