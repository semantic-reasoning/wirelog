# Lexical Source financial lifecycle component (#2300)

This component owns private financial birth, completion and physical retirement.
It supplies no Native resource authority and does not close #2300. Root/parent
ownership, operator routing and the remaining domains are separate work.

## Private controller lifecycle

Ordinary private Source birth now uses one immutable-identity claim. A genuine
CAS loss returns a financial retry before publication; allocation/mutex failure
consumes the claimed identity without publishing a controller. The two real
references are creation plus attachment. Generic unlimited private financiers
retain their existing zero-limit behavior.

The additive positive-only fresh constructor initializes the actual first
attempt on an unpublished allocation: id1, active, zero consumed, Normal class,
no prior report. It publishes only after mutex and all state initialization.
It accepts no existing controller and cannot reset cancellation or history.
Only the additive early checked-birth callback selects this constructor.

Private financial completion checks owner, identity, saved generation, limits,
consumption and the real two-reference pair under the controller mutex. It
observes cancellation and publishes the report under that same lock. Ordinary
Core FINISH remains unchanged and does not itself poll cancellation. The
Session financial wrapper records actual completion before later disposal;
a successor is never finished by an old saved-generation close. Separate final
retirement requires an unexposed exclusive pair and drops its actual attachment
and creation obligations only after preserving the completed report by value.

## Explicit early and final outcomes

Five additive early BANK modes distinguish protocol refusal, actual BEGIN,
its immediate zero-work checkpoint, financial failure, callbacks and completion.
A begun cancellation is still a real phase requiring FINISH. No-start failure
has no invented receipt. Session checked birth reports callback entry, its raw
result and actual bound ownership independently. A late BANK stop cannot erase
a genuinely bound Source. Older general phase APIs keep their ordering.

The additive final pair authenticates complete disjoint typed extents and

bridge then precedes metadata action B. Nothing follows the freed Source.
An uncalled A has a separate mandatory financial unwind. Complete outcome
values survive automatic scope expiry; retries use fresh metadata phases and
cannot replay close or an already delivered callback. These callbacks perform
financial/engine metadata work only and cannot borrow a Native owner.

## Checked early close under qualification

An additive active-only close authenticates the original Session/record/scope,
creator thread, allocation identity and actual Normal owner/ref2/saved generation
before its first same-lock financial checkpoint. A checked cancellation or work
stop still owns the two references and requires physical retirement. A copied,
stale, aliased or extra-reference input refuses before that checkpoint.

The synchronous caller keeps this financial pair unexposed and exclusive;
only cancellation may change. Its short borrowed tuple is not an ownership
certificate for arbitrary callers and grants no Native progress. The new BANK
sibling checkpoints that Source before acquiring a closing phase. If A is not
called, a distinct Source handoff precedes BANK completion, and another real
Source checkpoint precedes strict physical retirement after return. A-called
strict refusal leaves the actual lexical owner live; it never becomes no-A.
After any A entry the issuer never follows the borrowed Source pointer.

The returned values separate protocol, authorizer/acquisition/completion checks,
actual BANK BEGIN/checkpoint/finish, A-called/raw result, mandatory unwind and
physical closure. Already-closed scopes retrieve actual cached closure without
a new phase or reference drop. The existing close APIs and their inactive
positives retain their original bodies and behavior.
